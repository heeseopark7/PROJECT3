# ALU / MAC RTL 코드 해석 문서

작성일 2026-10-15 · 대상 브랜치 `claude/nice-galileo-e6r3qs` · 대상 폴더 `proj3_make/TOP/1_RTL`

이 문서는 RTL 코드를 **합성에 쓰는 사람**이 코드를 처음 열었을 때 구조, 파라미터, 동작, 검증 상태를 한 번에 이해하도록 쓴 해석서다. 모듈별 상세 설명은 `docs/module_notes/`, 스펙의 단일 출처는 `docs/ALU_MAC_design_note.md`다.

## 0. 한 장 요약

| 항목 | 내용 |
|---|---|
| 무엇 | RISC-V 방식 연산 10종 **ALU**와 곱해서 누적하는 **MAC**. 덧셈기 5종, 시프터 2종, 곱셈기 3종, MAC 파이프라인 3단계를 파라미터로 바꿔 끼울 수 있다. |
| 톱 모듈 | `alu_top`, `mac_top` (이 두 개가 합성 톱). 부분 측정용으로 `adder_top`, `alu_core`, `mul_top`도 단독으로 합성할 수 있다. |
| 파일 | RTL 17개 + 헤더 1개(`alu_defs.vh`), 합계 약 1,640줄. 파일 목록은 `rtl.f`. |
| 언어 | Verilog-2001만. 시스템 함수, `initial`, `#` 지연, 계층 참조 없음. |
| 변형 수 | ALU: 덧셈기 5 × 시프터 2 = 10조합. MAC: 곱셈기 3 × 덧셈기 5 × 파이프라인 단계 (1, 2, 3단; 3단은 구조형 곱셈기만). |
| 기능 검증 | Verilator 풀 볼륨 63개 시뮬 **FAIL 0**, iverilog 4-상태 55개 **FAIL 0**, 모든 구조 조합에서 출력 해시 **동일**. |
| 정적 검증 | lint(Verilator `-Wall`) 231개 구성 경고 0, Yosys 101개 구성 통과, 미구현 값 9종 컴파일 거부 확인. |
| 아직 안 한 것 | 합성(SDC, 스크립트, PPA 측정), 합성 후 게이트레벨 시뮬. 상용 합성 툴(Genus 등)로 읽어 본 적은 없다(Yosys로만 확인). |

## 1. 용어 풀이

처음 나올 때 한 줄로 풀어 둔 용어를 한곳에 모았다.

| 용어 | 뜻 |
|---|---|
| RTL | 레지스터와 그 사이 논리로 회로를 적은 코드. 합성 툴이 이걸 게이트로 바꾼다. |
| 조합 로직 / 순차 로직 | 입력이 바뀌면 출력이 바로 바뀌는 회로 / 클록 에지에서만 값을 저장하는 회로(레지스터). |
| 파라미터 | 모듈을 만들 때 정하는 상수(폭, 구조 번호 등). 합성 스크립트에서 바꿔 구조를 고른다. |
| `generate` | 파라미터에 따라 회로를 반복하거나 골라서 만드는 문법. |
| 패킹 벡터 | `wire [N-1:0]` 하나에 여러 신호를 이어 붙인 것. `v[k*W +: W]`는 그중 k번째 W비트 조각. |
| carry(올림) / propagate / generate | 덧셈에서 올림수 / "들어온 올림을 넘기는가(P=a^b)" / "스스로 올림을 만드는가(G=a&b)". |
| prefix 네트워크 | 모든 비트의 올림을 구간 단위로 합쳐 구하는 병렬 회로. Kogge-Stone, Brent-Kung이 이 종류. |
| CSA(carry-save 가산기) | 세 수를 더해 합 한 줄과 올림 한 줄로 내놓는 압축기. 올림이 옆으로 번지지 않는다. |
| 부분곱 | 곱셈을 손으로 할 때 쓰는 줄들. |
| Booth 인코딩 | 곱하는 수를 2비트씩 −2..+2 숫자로 바꿔 부분곱 줄 수를 절반으로 줄이는 방법. |
| Wallace 트리 | 여러 줄을 3줄씩 CSA로 묶어 두 줄이 될 때까지 줄이는 구조. |
| 파이프라인 / latency | 중간에 레지스터를 넣어 클록 주기를 줄이는 방법 / 입력이 들어간 뒤 결과가 보이기까지 걸리는 클록 에지 수. |
| critical path | 레지스터 사이에서 가장 오래 걸리는 경로. 클록 주기를 정한다. |
| lint | 코드를 실행하지 않고 문법/구조 문제를 찾는 검사. |
| 해시(HASH) | 테스트벤치가 모든 출력을 하나의 숫자로 접어 둔 것. 같은 자극에 출력이 완전히 같으면 해시도 같다. |

## 3. 합성에 쓰는 법

### 3.1 톱 모듈과 포트

**`alu_top`** (파라미터 `XLEN`, `ADDER_ARCH`, `SHIFTER_ARCH`)

| 포트 | 방향 | 폭 | 설명 |
|---|---|---|---|
| `i_clk` | in | 1 | 클록, 상승 에지만 사용 |
| `i_rst_n` | in | 1 | active-low 비동기 리셋 (해제는 클록에 동기되어 들어온다고 가정) |
| `i_valid` | in | 1 | 입력 유효 |
| `i_a`, `i_b` | in | XLEN | 피연산자 (시프트양은 `i_b` 하위 log2(XLEN)비트) |
| `i_alu_op` | in | 4 | 연산 코드 (5.1절) |
| `o_valid` | out | 1 | 결과 유효 |
| `o_result` | out | XLEN | 결과 (`o_valid=0`이면 don't care) |
| `o_flag_zero / neg / carry / ovf` | out | 1 | 플래그 4종 |

**`mac_top`** (파라미터 `A_W`, `ACC_W`, `MULT_ARCH`, `ADDER_ARCH`, `MAC_STAGES`)

| 포트 | 방향 | 폭 | 설명 |
|---|---|---|---|
| `i_clk`, `i_rst_n` | in | 1 | 클록 / 비동기 리셋 |
| `i_a`, `i_b` | in | A_W | signed 피연산자 |
| `i_en` | in | 1 | 1이면 `a×b`를 누산 |
| `i_clr` | in | 1 | 1이면 누산기를 0으로 (`i_en`보다 우선) |
| `o_acc` | out | ACC_W | 누산 결과 (valid 포트 없음: 리셋 이후 항상 정의됨) |

### 3.2 변형 선택 파라미터

| 파라미터 | 값 | 기본 | 비고 |
|---|---|---|---|
| `XLEN` | 8, 16, 32 | 32 | ALU 비트폭 (그 외는 컴파일 거부) |
| `ADDER_ARCH` | 0 RCA, 1 CLA, 2 Kogge-Stone, 3 Brent-Kung, 4 BEH(`+`) | 4 | 모든 덧셈에 적용 |
| `SHIFTER_ARCH` | 0 loop, 1 barrel | 1 | |
| `A_W` | 4, 8, 16 | 16 | MAC 입력 폭 (Booth는 짝수) |
| `ACC_W` | `2·A_W + 8` | 40 | 누산기 폭(파생) |
| `MULT_ARCH` | 0 BEH(`*`), 1 Array, 2 Booth+Wallace | 0 | |
| `MAC_STAGES` | 1, 2, 3 | 1 | 3은 `MULT_ARCH` 1 또는 2일 때만 |

**기준선 조합**: `ADDER_ARCH=4`, `SHIFTER_ARCH=1`, `MULT_ARCH=0`, `MAC_STAGES=1`. 비교 실험에서는 한 번에 하나만 바꾼다. 곱셈기/MAC 비교에서는 `ADDER_ARCH=4`로 고정해 덧셈기 차이가 섞이지 않게 한다.

**지원하지 않는 값은 컴파일(elaboration)이 실패한다.** 다른 구현으로 조용히 대체되지 않는다. 이를 위해 해당 `generate` 분기가 존재하지 않는 모듈(`adder_arch_not_implemented` 등)을 인스턴스한다. 회귀가 거부 동작 9종을 매번 확인한다: `ADDER_ARCH=5`, `SHIFTER_ARCH=2`, `MULT_ARCH=3`, carry-save 입구에 `MULT_ARCH=0/3`, `A_W=6`, `MAC_STAGES=4`, `MAC_STAGES=3 + MULT_ARCH=0`, `mac_top A_W=6`.

### 3.3 합성 측정 단위

| 단위 | 합성 톱 | 바꾸는 변수 | 목적 |
|---|---|---|---|
| T1 | `adder_top` (`W`는 2~64 어디든) | `ADDER_ARCH` | 덧셈기 구조 자체의 차이 |
| T2 | `alu_core` | `ADDER_ARCH`, `SHIFTER_ARCH` | 시프터/플래그 경로가 덧셈기 차이를 가리는가 |
| T3 | `alu_top` | `ADDER_ARCH`, `SHIFTER_ARCH` | 레지스터 사이 경로로 클록 주기 sweep |
| M1 | `mul_top` (`ADDER_ARCH=4`) | `MULT_ARCH` | 곱셈기 구조 차이 |
| M2 | `mac_top` | `MULT_ARCH`, `MAC_STAGES` | 파이프라인 단별 latency와 최대 주파수 |

`adder_top`의 폭 `W`는 ALU/MAC 지원 폭과 별개로 2~64에서 일반화돼 있다(lint, Yosys로 W=8/16/24/32/40/64 확인). 그래서 T1에서 W를 올려 가며 구조 차이가 벌어지는 모양을 볼 수 있다. ALU `XLEN`과 MAC `A_W`는 64를 지원하지 않는다(설계 결정 O8).

### 3.4 파라미터 지정 예 (Yosys로 확인한 것)

```
read_verilog -I<1_RTL 경로> <rtl.f의 파일들>
hierarchy -check -top alu_top -chparam XLEN 16 -chparam ADDER_ARCH 2 -chparam SHIFTER_ARCH 1
hierarchy -check -top mac_top -chparam MULT_ARCH 2 -chparam MAC_STAGES 3 -chparam ADDER_ARCH 4
hierarchy -check -top adder_top -chparam W 64 -chparam ADDER_ARCH 3
```

`alu_defs.vh`를 찾으려면 `1_RTL`을 include 경로로 줘야 한다(`rtl.f`의 `+incdir+.`). 다른 합성 툴의 파라미터 덮어쓰기 문법은 해당 툴 문서를 따른다(이 프로젝트에서는 Yosys로만 확인했다).

### 3.5 합성 리포트를 읽을 때 쓰는 인스턴스 이름

모듈 경계는 변형마다 유지되도록 인스턴스 이름을 고정했다. 구조가 합성 후에도 유지됐는지 볼 때 이 경계를 기준으로 삼는다.

| 위치 | 인스턴스 경로 |
|---|---|
| ALU | `alu_top.u_core` → `alu_core.u_adder`(= `adder_top`), `alu_core.u_shifter`(= `alu_shifter`) |
| 덧셈기 | `adder_top.g_rca / g_cla / g_ks / g_bk / g_beh` 안의 `u_adder` |
| 시프터 | `alu_shifter.g_loop / g_barrel` 안의 `u_core` |
| MAC 1, 2단 | `mac_top.g_stage1 / g_stage2` 안의 `u_mul`(= `mul_top`), 공통 누산 덧셈기 `mac_top.u_adder` |
| MAC 3단 | `mac_top.g_stage3.u_csa`(= `mul_csa_top`, 압축), `mac_top.g_stage3.u_final`(= `adder_top`, 곱셈 마지막 합산), `mac_top.u_adder`(누산) |
| 곱셈기 | `mul_top.g_beh.u_mul`, 또는 `mul_top.g_csa.u_csa`(= `mul_csa_top`) + `mul_top.g_csa.u_adder` |
| 구조형 곱셈기 | `mul_csa_top.g_array.u_mul` / `g_booth.u_mul` |

## 4. 모든 모듈에 공통인 설계 원칙

1. **포트 동일.** 같은 모듈의 변형은 포트가 완전히 같다. 하나의 SDC와 하나의 테스트벤치를 모든 변형에 재사용하기 위해서다.
2. **산술 연산자 위치.** `+ - *`는 `adder_beh`, `mul_beh`, 테스트벤치 기준 모델에서만 데이터에 쓴다. 다른 곳에 두면 합성 툴이 구조를 자체 선택해 비교가 무의미해진다. 나머지 RTL의 `+ - *`는 elaboration 때 계산되는 상수뿐이다(localparam, `generate` 반복 변수, 상수 함수, 벡터 조각 위치 계산). 스캔으로 확인했다.
3. **리셋 정책.** 상태를 가진 레지스터(`valid`, `en/clr` 파이프라인, `acc_q`)만 비동기 리셋한다. 데이터 레지스터(`a_q`, `b_q`, `op_q`, `result_q`, `flag_q`, `p_q`, `s_q`, `c_q`)는 리셋도 enable도 없다. 면적과 D 입력 경로를 줄이고 모든 변형에 똑같이 적용해 공정성을 지키기 위해서다. 그래서 `o_valid=0`인 동안 결과 값은 모른다(X일 수 있다).
4. **패킹 벡터와 계층 참조 금지.** 단(stage)이나 줄(row)을 잇는 중간 신호는 패킹 벡터 하나의 조각으로 둔다. 생성 블록 안의 net을 이름으로 직접 읽는 계층 참조는 쓰지 않는다(상용 합성 툴 호환이 확인되지 않아서). 벡터 조각끼리 이어진 것이 lint에 순환으로 보이는 경우 `/* verilator split_var */` 주석(lint 전용 힌트)을 붙였다. 이 주석은 합성에 영향이 없다.
5. **lint 경고 해석.** 남는 경고는 이유를 주석에 적고 해당 net에만 `lint_off`를 걸었다. 전부 "사용하지 않는 비트"이고 다음과 같다: `mac_top`/`mul_top`의 덧셈기 carry-out(결과를 2^N으로 나머지 취하므로 불필요), `adder_ks`/`adder_bk`의 마지막 단 P 비트, `mul_array_csa`/`mul_booth_csa`의 맨 위 비트에서 나가는 올림(버림). 합성이 알아서 지운다.
6. **Verilog-2001만.** `$clog2` 같은 시스템 함수 없음(폭은 `XLEN`이 8/16/32뿐이라 직접 계산), `initial`/`#`/`$display` 없음, 파일마다 `` `default_nettype none `` ~ `` `default_nettype wire `` 쌍(17개 파일 모두 확인), `timescale` 없음.
7. **이름 규칙.** 입력 `i_`, 출력 `o_`, 내부 wire `w_`, 레지스터 출력 `_q`, active-low `_n`. 파라미터는 대문자, 신호는 snake_case.
8. **모든 모듈 헤더에 목적, 구조, latency를 적었다.**

## 5. ALU 해석

### 5.1 연산 코드 `alu_defs.vh`

`i_alu_op[3:0]`은 RISC-V의 `{funct7[5], funct3}`와 같은 값이다.

| 코드 | 연산 | 의미 | 쓰는 유닛 |
|---|---|---|---|
| `0000` | ADD | a + b | 덧셈기 |
| `1000` | SUB | a − b | 덧셈기 (빼기 모드) |
| `0001` | SLL | a << shamt | 시프터 (왼쪽) |
| `0010` | SLT | 부호 있는 a < b 이면 1 | 덧셈기 (빼기 모드) |
| `0011` | SLTU | 부호 없는 a < b 이면 1 | 덧셈기 (빼기 모드) |
| `0100` | XOR | | 논리 |
| `0101` | SRL | a >> shamt (0 채움) | 시프터 (오른쪽) |
| `1101` | SRA | a >>> shamt (부호 채움) | 시프터 (오른쪽, 산술) |
| `0110` | OR | | 논리 |
| `0111` | AND | | 논리 |
| 그 외 6개 | Reserved | result = 0, zero = 1, 나머지 플래그 0 | 없음 |

### 5.2 `alu_top` : 레지스터를 씌운 래퍼

```
          ┌─────────── 입력 레지스터 ───────────┐     ┌───────── 출력 레지스터 ─────────┐
 i_a ────▶│ a_q  (리셋 없음)                     │     │ result_q (리셋 없음)             │──▶ o_result
 i_b ────▶│ b_q  (리셋 없음)                     ├──▶  alu_core  ──▶ flag_q   (리셋 없음)  │──▶ o_flag_*
 i_alu_op▶│ op_q (리셋 없음)                     │     │                                  │
 i_valid ▶│ valid_in_q  (비동기 리셋)            ├────────────────▶ valid_out_q (비동기 리셋)│──▶ o_valid
          └──────────────────────────────────────┘     └──────────────────────────────────┘
```

- **왜 감쌌나**: 합성 비교에서 입출력 핀 제약의 영향을 빼고 "레지스터 → 조합 로직 → 레지스터" 경로만 공정하게 비교하기 위해서다.
- **latency 2에지**, 처리량은 매 클록 1건. 에지 n에 입력이 `a_q` 등에 잡히고, 에지 n+1에 `alu_core` 결과가 `result_q`에 잡힌다.

```
에지        1       2       3       4
입력 포트   X0      X1      X2      X3
입력 레지   X0      X1      X2      X3        (a_q, b_q, op_q)
출력 레지   무효    f(X0)   f(X1)   f(X2)     (result_q, flag_q)
```

- **레지스터 수** (XLEN=32): 입력 `32 + 32 + 4 + 1 = 69`, 출력 `32 + 4 + 1 = 37`, 합계 106. 이 중 리셋을 가진 건 valid 2개뿐이다.
- 코드 핵심: 데이터는 `always @(posedge i_clk)`, valid는 `always @(posedge i_clk or negedge i_rst_n)`로 두 블록으로 나눠 리셋 유무를 구분했다. 플래그는 `flag_q <= {zero, neg, carry, ovf}` 한 줄이다.

### 5.3 `alu_core` : 계산부 (조합)

```
 i_a ──┬────────────────────────────────┐
       │        ┌──────┐   w_b_eff      ▼
 i_b ──┼──XOR──▶│ adder│──▶ sum, cout ──▶ ovf, SLT 비트, SLTU 비트 ─┐
       │  ▲     │ _top │                                             │
 op ───┼──┴ sub ┴──────┘                                            ▼
       │                                                        ┌────────┐
       ├──▶ alu_shifter ─────────────────────────────────────▶ │  case  │──▶ o_result ──▶ zero / neg
       └──▶ XOR / OR / AND ──────────────────────────────────▶ │ (op)   │──▶ carry, ovf (4개 연산만)
                                                                └────────┘
```

**덧셈기 공유** (ADD, SUB, SLT, SLTU가 덧셈기 하나를 쓴다)

| 신호 | 정의 |
|---|---|
| `sub` | 연산이 SUB, SLT, SLTU 중 하나이면 1 |
| `b_eff` | `i_b ^ {XLEN{sub}}` (빼기이면 b를 뒤집는다) |
| `{cout, sum}` | `i_a + b_eff + sub` (`adder_top`, `i_cin = sub`) |
| `ovf` | `(a[M] == b_eff[M]) & (sum[M] != a[M])` (M = 최상위 비트) |
| SLT 결과 | `sum[M] ^ ovf` |
| SLTU 결과 | `~cout` |

- 빼기 `a − b`는 `a + ~b + 1`이다(2의 보수). 이때 carry-out이 1이면 "빌림 없음"(a ≥ b, 부호 없음)이라서 SLTU는 `~cout`이다.
- **계산 예 (XLEN=32)**
  - `SUB 0x00000000 − 1`: `b_eff = 0xFFFFFFFE`, `0 + 0xFFFFFFFE + 1 = 0xFFFFFFFF`, `cout = 0` → 결과 `0xFFFFFFFF`, 플래그 `z=0 n=1 c=0 v=0`.
  - `SLT 0x80000000 < 1`: `sum = 0x7FFFFFFF`, `cout = 1`, `a[M]=1`과 `b_eff[M]=1`이 같은데 `sum[M]=0`이 달라서 `ovf = 1`, SLT = `0 ^ 1 = 1`(맞다: 가장 작은 음수는 1보다 작다). SLTU = `~cout = 0`(부호 없이는 0x80000000이 더 크다).
- **결과 선택과 플래그**: `always @*` 안의 `case`가 결과를 고른다. 맨 위에서 `result/carry/ovf`에 기본값 0을 주고, `default`(Reserved)는 결과 0. `zero = (result == 0)`, `neg = result[M]`는 **선택된 결과**에서 뽑는다. 그래서 SLT/SLTU의 neg는 자동으로 0이고 Reserved는 zero = 1이다. carry/ovf는 ADD/SUB/SLT/SLTU 분기에서만 덧셈기 값을 쓴다.
- 덧셈기 인스턴스는 **하나뿐**이며 `b_eff` 반전과 `cin = sub` 뒤에 있다. 이 구조 때문에 `sub` 신호가 XLEN+1개 부하를 구동한다(후속 PnR 관찰 항목).

### 5.4 시프터 : `alu_shifter` + `shr_*`

시프터는 **오른쪽 시프트 코어 하나**만 만들고 왼쪽은 입출력 비트를 뒤집어 처리한다.

- SRL/SRA: 입력을 그대로 코어에 넣는다. 채움 비트 `fill = i_right & i_arith & i_din[M]` (SRA이고 음수일 때만 1).
- SLL: `비트 뒤집기 → 오른쪽 시프트 → 비트 뒤집기`. 8비트 예: `0b00000011`을 2칸 왼쪽: 뒤집으면 `11000000` → 오른쪽 2칸 `00110000` → 다시 뒤집으면 `00001100`(= 3 << 2 = 12).
- 시프트양은 `i_b`의 하위 log2(XLEN)비트만 쓴다(상위 비트는 무시).
- 비용: 면적은 줄지만 입출력에 2:1 mux가 하나씩 더 붙는다(후속 합성에서 확인).

| 코어 | 구조 | 단 수 | 이론 mux 수 |
|---|---|---|---|
| `shr_barrel` (기본) | `shamt[k]=1`이면 2^k칸 미는 단 | log2(XLEN) = 5 (XLEN=32) | 약 XLEN·log2(XLEN) |
| `shr_loop` | `shamt > k`이면 1칸 미는 단 | XLEN − 1 = 31 | 약 XLEN² |

`shr_loop`은 **가장 길고 큰 후보**, `shr_barrel`은 **짧고 작은 후보**다. 기준선을 barrel로 둔 이유는 loop를 기준선으로 두면 시프터가 항상 critical path가 되어 덧셈기 비교를 가리기 때문이다. 두 코어 모두 가변 시프트 연산자(`<<`, `>>`)를 쓰지 않고 mux를 직접 그렸다(툴이 구조를 고르는 문법이라서).

### 5.5 `adder_top`과 덧셈기 5종

`adder_top`은 `generate if`로 `ADDER_ARCH`에 맞는 하나를 인스턴스한다. 포트는 모두 `i_a, i_b, i_cin → o_sum, o_cout`.

| 구조 | 한 줄 요약 | 논리 단 수 | 셀 수 (W=32, 이론) |
|---|---|---|---|
| **RCA** (0) | 전가산기를 일렬로, 올림이 줄줄이 | W = 32 | 전가산기 32개 |
| **CLA** (1) | 4개씩 묶어 올림을 미리 계산하는 radix-4 트리 | 약 2·log4(W) 층의 AND-OR | 노드 43개 (W=32) |
| **KS** (2) Kogge-Stone | 모든 비트가 매 단마다 `2^l`칸 아래와 합쳐진다 | log2(W) = 5 | prefix 셀 129개 |
| **BK** (3) Brent-Kung | 나무처럼 모았다가 내려오며 채운다 | 2·log2(W) − 1 = 9 | prefix 셀 57개 |
| **BEH** (4, 기본) | `+` 한 줄, 구조는 툴이 선택 | 툴 선택 | 툴 선택 |

(표의 KS 129개, BK 57개, CLA 43개는 코드의 `generate` 조건을 그대로 세어 확인한 값이다. W별 값은 아래 표.)

| W | 8 | 16 | 24 | 32 | 40 | 64 |
|---|---|---|---|---|---|---|
| KS 단 / 셀 | 3 / 17 | 4 / 49 | 5 / 89 | 5 / 129 | 6 / 177 | 6 / 321 |
| BK 단 / 셀 | 5 / 11 | 7 / 26 | 9 / 41 | 9 / 57 | 11 / 72 | 11 / 120 |
| CLA 레벨별 노드 | 8,2,1 | 16,4,1 | 24,6,2,1 | 32,8,2,1 | 40,10,3,1 | 64,16,4,1 |

**공통 개념**: 비트마다 `p = a^b`, `g = a&b`이고, 합은 `sum_i = p_i ^ c_i`, 올림은 `c_(i+1) = g_i | (p_i & c_i)`. 구조마다 `c_i`를 만드는 방식이 다르다.

- **`adder_rca`**: 올림 사슬 `w_c[W:0]`를 패킹 벡터로 두고 `generate`가 비트마다 `assign` 두 줄을 쓴다(`sum`, 다음 올림). 가장 작고 가장 느린 구조다.
- **`adder_cla`**: 노드는 `(G, P)` 쌍(그 구간이 올림을 만든다/넘긴다). 레벨 0은 비트, 레벨 1은 4비트 블록, 레벨 2는 16비트 그룹 ... 뿌리 하나까지 4개씩 묶는다. 위로 올라갈 때 `G = g3 | p3·g2 | p3·p2·g1 | p3·p2·p1·g0`을 AND-OR 한 층으로 계산하고, 아래로 내려올 때 그룹 안 각 자식의 올림을 같은 식으로 계산한다. 마지막 묶음이 1~3개여도 되므로 W가 4의 배수일 필요가 없다. 트리 모양(레벨별 노드 수)은 상수 함수로 elaboration 때 계산한다.
- **`adder_ks`**: carry-in을 비트 0의 generate에 흡수(`g0' = g0 | (p0 & cin)`)한 뒤, 단 `l`에서 `i ≥ 2^l`인 모든 비트가 `G_i ← G_i | (P_i & G_(i−2^l))`, `P_i ← P_i & P_(i−2^l)`을 계산한다. 마지막 단 뒤 `G_i`가 비트 i의 올림이다. 단마다 패킹 벡터 `w_g`, `w_p`의 한 조각이다. 셀과 배선이 가장 많은 대신 단 수가 가장 적다.
- **`adder_bk`**: 올라가는 단(up-sweep)은 `(i+1)`이 `2^(d+1)`의 배수인 비트가 `i−2^d`와 합쳐지고, 내려오는 단(down-sweep)은 `(i+1) = 3·2^d + t·2^(d+1)`인 비트가 합쳐진다. 총 `2L−1`단. 존재하지 않는 비트(인덱스 ≥ W)는 만들지 않고, 모든 셀이 자기보다 낮은 인덱스만 읽으므로 W가 2의 거듭제곱이 아니어도 된다.
- **`adder_beh`**: `{1'b0,a} + {1'b0,b} + cin` 한 줄. `+`가 허용되는 두 곳 중 하나다.

### 5.6 합성에서 볼 가설 (수치 단정 아님)

- 덧셈기 지연은 RCA가 가장 크고 KS가 가장 작을 것이며, 면적과 배선은 반대로 KS가 가장 클 것이다. CLA와 BK는 그 사이의 서로 다른 지점일 것이다.
- `alu_core`(T2)에서는 `b XOR sub` → 덧셈기 → ovf/SLT → 결과 mux → zero 검출(P1 경로)이 가장 길 가능성이 있다. 특히 결과 mux 뒤의 zero 검출(OR 트리)이 길어질 수 있어서, 덧셈기 차이가 이 경로에 가려지는지가 T2의 질문이다.
- BEH는 합성 툴이 제약에 맞춰 구조를 고르므로, 클록 목표가 빡빡해지면 RTL 구조형과 비슷해질 수 있다. 구조가 합성 후에도 유지되는지는 모듈 경계(3.5절)와 critical path 레벨 수로 확인한다.

## 6. MAC 해석

### 6.1 동작 정의 (`mac_top`)

매 클록 에지에서 명령 `(i_clr, i_en, i_a, i_b)`를 받고 다음 중 하나를 한다. 피연산자는 2의 보수 signed다.

| 조건 | 동작 |
|---|---|
| `i_clr = 1` | `acc ← 0` (곱은 무시, `i_en`보다 우선) |
| `i_clr = 0, i_en = 1` | `acc ← acc + sext(a×b)` (mod 2^ACC_W, 포화 없이 wrap) |
| 둘 다 0 | `acc` 유지 |

곱은 2·A_W비트 signed이고 `ACC_W`로 **부호 확장**(음수면 위쪽을 1로 채움)해서 더한다. `ACC_W = 2·A_W + 8`(가드 비트 8개)이라서 가장 큰 곱 `(−2^(A_W−1))² = 2^(2·A_W−2)`를 연속으로 더하면 **511번까지는 범위 안, 512번째에 wrap**한다(어느 A_W든 같다: 범위 한계 `2^(ACC_W−1)`을 최악의 곱 `2^(2·A_W−2)`로 나누면 `2^9 = 512`).

### 6.2 구조 : 앞부분은 단계마다 다르고 누산부는 모두 같다

```
MAC_STAGES = 1  입력레지 ─▶ [ 곱셈 ] ───────────────────────────────▶ [ 누산 ] ─▶ acc_q          latency 2
MAC_STAGES = 2  입력레지 ─▶ [ 곱셈 ] ─▶ p_q ───────────────────────▶ [ 누산 ] ─▶ acc_q          latency 3
MAC_STAGES = 3  입력레지 ─▶ [ 부분곱 생성·압축 ] ─▶ s_q,c_q ─▶ [ 최종합산 ] ─▶ p_q ─▶ [ 누산 ] ─▶ acc_q   latency 4
```

- **누산 루프(`acc_q → 덧셈기 → acc_q`)는 모든 단계에서 1사이클이고 루프 안에 레지스터가 없다.** 루프에 레지스터를 넣으면 "클록마다 한 번 더하기"가 "두 클록에 한 번"으로 바뀌어 결과가 달라진다. 그래서 분할은 곱셈 쪽에서만 한다.
- **제어(`en`, `clr`)는 데이터와 같은 단수만큼 레지스터를 지난다.** 그래야 어느 단계에서나 같은 명령이 같은 순서로 반영된다.
- **리셋**: `acc_q`와 `en/clr` 레지스터만 비동기 리셋. `a_q, b_q, p_q, s_q, c_q`는 리셋 없음. 리셋 직후 `en = clr = 0`이라 쓰레기 데이터가 누산에 반영되지 않아 `o_acc`가 항상 정의된다.
- **3단은 구조형 곱셈기 전용**. BEH(`*`)는 곱셈 내부를 툴이 정해서 "압축 끝"이라는 경계가 없다. `MULT_ARCH=0`과 `MAC_STAGES=3`을 같이 주면 컴파일 에러다.
- **레지스터 비트 수** (A_W=16, ACC_W=40): 1단 74, 2단 108, 3단 174 (설계 노트 표와 같다).

| MAC_STAGES | 입력 (a_q 16 + b_q 16 + en/clr 2) | 단 사이 | acc_q | 합계 |
|---|---|---|---|---|
| 1 | 34 | 0 | 40 | 74 |
| 2 | 34 | `p_q` 32 + 제어 2 = 34 | 40 | 108 |
| 3 | 34 | `s_q,c_q` 64 + 2 + `p_q` 32 + 2 = 100 | 40 | 174 |

코드 구조: `generate if`가 `MAC_STAGES`와 지원 조건으로 `g_stage1/2/3`을 고르고, 각 분기는 `w_p_acc`(누산할 곱), `w_en_acc`, `w_clr_acc` 세 신호만 공통부로 내보낸다. 공통부(누산 덧셈, `clr → en → 유지` 선택, `acc_q`)는 한 번만 쓰여 있다. 지원하지 않는 조합은 `g_unsupported`에서 존재하지 않는 모듈을 인스턴스해 컴파일이 실패한다.

### 6.3 곱셈기 선택 : `mul_top`, `mul_beh`, `mul_csa_top`

- `mul_beh`: `o_p = i_a * i_b` (signed). 기준선. `*`가 허용되는 두 곳 중 하나.
- `mul_top`: `MULT_ARCH = 0`이면 `mul_beh`. 1이나 2이면 `mul_csa_top`이 `o_s`, `o_c`(두 벡터)를 만들고 `adder_top`(`ADDER_ARCH`, 폭 2·A_W)이 마지막 덧셈 `o_p = o_s + o_c`를 한다. 곱은 2^(2·A_W)로 나머지를 취한 값이라 `adder_top`의 carry-out은 쓰지 않는다.
- `mul_csa_top`: `MULT_ARCH = 1`은 `mul_array_csa`, `2`는 `mul_booth_csa`. 약속: `o_s + o_c ≡ a×b (mod 2^(2·A_W))`. 이 두 벡터를 결과로 쓰는 곳이 3단 MAC의 `s_q, c_q`다.

### 6.4 `mul_array_csa` : Array + Baugh-Wooley

부분곱 줄이 A_W개인 배열 곱셈기이고 줄은 CSA 줄로 하나씩 직렬로 더한다.

**부호 처리 (Baugh-Wooley)**. 2의 보수에서 최상위 비트의 가중치는 **음수**(−2^(n−1))다. 그래서 부분곱 중 "한쪽만 부호 비트"인 항들은 빼야 한다. `−x·2^k = (~x)·2^k − 2^k`이므로 그 비트들만 **반전(NAND)** 하고, 빼야 할 `−2^k`들을 모으면 상수 `2^n + 2^(2n−1)`(mod 2^(2n))가 된다. 즉:

- 줄 `i < n−1`: 맨 위 비트 `a[n−1] & b[i]`를 반전.
- 마지막 줄 `i = n−1`: 아래 `n−1`개 비트 `a[j] & b[n−1]`를 반전. 맨 위 비트 `a[n−1] & b[n−1]`는 그대로 AND.
- 비트 `n`과 비트 `2n−1`에 상수 1을 더한다 (A_W=4이면 `0x90`, 8이면 `0x8100`, 16이면 `0x80010000`).

**구조**: 패킹 벡터 `w_rows`의 줄 r은 `{maj(P_W비트), sum(P_W비트)}`다. 줄 0은 시작값 `{0, 상수}`이고, 줄 i+1은 줄 i에 부분곱 i를 더한 결과다. `sum = x_s ^ x_c ^ pp`, `maj = (x_s&x_c) | (x_s&pp) | (x_c&pp)`, 올림 벡터는 `maj`를 왼쪽으로 1칸 민 것이고, 맨 위 비트 밖으로 나가는 올림은 버린다(2^(2n) 나머지). 줄마다 `assign` 하나.

### 6.5 `mul_booth_csa` : Booth radix-4 + Wallace 트리

**Booth 인코딩**: `b`를 `(b[2k+1], b[2k], b[2k−1])` 세 비트씩 봐서(맨 아래 `b[−1]=0`) 숫자 `d_k = −2·b[2k+1] + b[2k] + b[2k−1]`(−2..+2)로 바꾼다. 줄이 A_W개에서 **A_W/2개**로 줄어든다. 예: `b = −7 = 1001`이면 `d_0 = +1`, `d_1 = −2`이고 `1·4^0 + (−2)·4^1 = −7`.

| 신호 | 식 | 뜻 |
|---|---|---|
| `one` | `b[2k] ^ b[2k−1]` | `|d| = 1` |
| `two` | `(b[2k+1]&~b[2k]&~b[2k−1]) | (~b[2k+1]&b[2k]&b[2k−1])` | `|d| = 2` |
| `neg` | `b[2k+1]` | 음수 (빼기) |

**부분곱 줄**: `a`(n+1비트로 부호 확장) 또는 `2a`를 `one`/`two`로 고르고, `neg`와 XOR해서 음수는 1의 보수로 만든다. 빠진 "+1"은 `neg` 비트로 줄 k의 자리(2k)에 따로 더한다.

**부호 확장 제거 (Baugh-Wooley와 같은 원리)**: 줄의 부호 비트 s는 가중치 −2^n이다. `−s·2^n = (~s)·2^n − 2^n`이므로 줄마다 부호 자리에 `~s`를 놓고, 빠진 `−2^(n+2k)` 항들을 모아 상수 `K = −2^n·(2^n−1)/3 (mod 2^(2n))`로 한 번에 더한다 (A_W=4이면 `0xB0`, 8이면 `0xAB00`, 16이면 `0xAAAB0000`).

**상수 줄 하나로 합치기**: K의 아래쪽 n비트는 0이고 `neg` 비트들은 아래쪽 n비트(짝수 자리)에만 있어서 겹치지 않는다. 둘을 **줄 하나**에 넣어 트리 입력이 `A_W/2 + 1`줄이 된다.

**Wallace 트리**: 줄을 3개씩 묶어 합 줄과 올림 줄로 바꾸고 남는 줄은 그대로 통과시킨다. 두 줄이 남으면 끝.

| A_W | Array 줄 수 (직렬 CSA 단) | Booth 입력 줄 수 | Wallace 단 (줄 수 변화) |
|---|---|---|---|
| 4 | 4 | 3 | 1단 (3 → 2) |
| 8 | 8 | 5 | 3단 (5 → 4 → 3 → 2) |
| 16 | 16 | 9 | 4단 (9 → 6 → 4 → 3 → 2) |

줄 수와 단 수는 상수 함수로 elaboration 때 계산하고, 모든 단의 모든 줄은 패킹 벡터 `w_all`의 조각 `(단 시작 위치 + 줄 번호)·P_W`다. 그래서 세 크기를 따로 그리지 않고 `generate` 한 벌로 만든다.

### 6.6 합성에서 볼 가설 (수치 단정 아님)

- **곱셈기(M1)**: Array는 깊이가 줄 수(약 A_W)에 비례해 가장 깊고 규칙적이다. Booth는 줄이 절반이고 트리 단이 적어 깊이가 짧을 것이지만, 인코더와 선택 mux 때문에 줄당 셀과 배선이 복잡하다. A_W=4, 8에서는 차이가 작거나 뒤집힐 수 있다. BEH가 이 둘 중 하나와 비슷한 구조로 재구성되는지가 핵심 질문이다.
- **MAC(M2)**: 1단은 `a_q/b_q → 곱셈 → 누산 덧셈 → acc_q`(Q1)가 가장 길 가능성이 크다. 2단은 곱셈 경로(Q3)가 짧아지지만 누산 루프(Q2: `acc_q → 덧셈 → acc_q`)는 그대로라서 클록 주기에 하한이 생긴다. 3단은 곱셈을 또 나눠 더 짧아지지만 레지스터가 늘어(74 → 108 → 174비트) 면적이 커진다. Q2 하한 때문에 이득이 줄어드는 지점을 찾는 것이 파이프라인 비교의 핵심이다.

### 7.1 테스트벤치 7개

### 7.2 해시(HASH)로 보는 "구조 동등성"

각 테스트벤치는 모든 출력을 하나의 32비트 값으로 접어 `HASH`로 출력한다. 같은 자극에서 모든 구조 조합이 같은 해시를 내야 한다. 이것이 "구조를 바꿔도 기능은 비트 단위로 같다"는 증거다.

- 덧셈기 5종, 시프터 2종, `alu_core` 10조합, `alu_top` 10조합, 곱셈기(BEH/Array/Booth × 덧셈기 5종), MAC(곱셈기 3종 × 덧셈기 5종 × 단계)에서 모두 해시가 같다.
- MAC은 지연 보정 후의 값을 해시하므로 `MAC_STAGES`가 1, 2, 3이어도 같다.
- 리셋이 섞이면 단계별로 파이프라인 안에 있던 명령이 버려지는 양이 달라서 해시를 비교할 수 없다. 그래서 해시는 리셋 없는 구간(A 단계)에서만 접는다.

### 7.3 자체 난수 발생기

테스트벤치는 `$random(seed)` 대신 안에 둔 **xorshift32** 난수를 쓴다. 시뮬레이터마다(그리고 인스턴스 실행 순서마다) `$random(seed)`가 다르게 동작해서 같은 자극이라도 해시가 달라졌기 때문이다. 이제 어떤 시뮬레이터에서도 자극이 똑같고, 한 문장에서 난수를 여러 번 부를 때의 평가 순서 문제를 피하려고 한 줄에 한 번씩 순서대로 뽑는다.

### 7.4 시뮬레이터 두 개를 쓰는 이유

| | Phase 1 : Verilator | Phase 2 : iverilog |
|---|---|---|
| 목적 | **대량 벡터** (100만, 8비트 전수) | **4-상태**(X/Z 검사)와 **Verilog-2001 준수**(`-g2001 -Wall`) |

### 8.1 합성 담당자가 먼저 볼 것

- [ ] 톱 모듈: `alu_top`, `mac_top` (측정 단위별 톱은 3.3절).
- [ ] 파일 목록: `1_RTL/rtl.f`. include 경로: `1_RTL`.
- [ ] 클록 하나(`i_clk`), 비동기 active-low 리셋(`i_rst_n`). 입력 포트에서 클록까지 별도 제약이 필요 없도록 입출력은 모두 레지스터 뒤/앞에 있다(`alu_top`, `mac_top`).
- [ ] 한 번에 하나만 바꾸기: 기준선(`ADDER_ARCH=4`, `SHIFTER_ARCH=1`, `MULT_ARCH=0`, `MAC_STAGES=1`) 기준으로 비교.
- [ ] 계층 해제(ungroup)를 하면 3.5절의 모듈 경계가 사라진다. 구조 유지 여부를 볼 거라면 경계를 유지하거나, 해제 여부를 모든 실험에 똑같이 고정할 것.
- [ ] 리포트에서 critical path의 단 수와 셀 수로 구조가 유지됐는지 확인. 유지되지 않으면 그 사실 자체를 결과로 기록.

### 8.2 코드에 남아 있는 주석 지시문 (합성에는 영향 없음)

| 지시문 | 위치 | 이유 |
|---|---|---|
| `/* verilator split_var */` | `adder_rca`, `adder_ks`, `adder_bk`, `adder_cla`, `shr_barrel`, `shr_loop`, `mul_array_csa`, `mul_booth_csa` | 패킹 벡터의 조각들이 서로 이어진 것을 lint가 순환으로 오해하지 않게 함 |
| `/* verilator lint_off UNUSEDSIGNAL */` | 덧셈기 carry-out(`mac_top`, `mul_top`), `adder_ks`/`adder_bk`의 마지막 P, `mul_array_csa`/`mul_booth_csa`의 맨 위 올림 비트 | 일부러 안 읽는 비트. 합성이 지움 |

### 8.3 알려진 한계 (정직하게)

- **상용 합성 툴로 읽어 본 적이 없다.** Yosys(`read_verilog`, `hierarchy`, `proc`, `flatten`, `check -assert`)로만 101개 구성을 확인했다. 계층 참조는 없앴지만, 상수 함수(`function`을 `localparam` 초기값으로 호출)와 `generate` 안 `localparam` 계산은 상용 툴에서 한 번 읽어 봐야 한다.
- **합성 후 게이트레벨 시뮬레이션은 하지 않았다.** 데이터 레지스터에 리셋이 없으므로 리셋 직후 `o_valid=0`인 동안 `o_result`/플래그가 X일 수 있다(스펙대로 don't care). 게이트레벨 시뮬에서 X가 보여도 `o_valid=0`이면 정상이다.
- **지원 범위**: `XLEN` 8/16/32, `A_W` 4/8/16. 64비트는 지원하지 않는다(O8). `adder_top`만 `W` 2~64.
- **MAC_STAGES는 최대 3**, 3은 구조형 곱셈기 전용, `A_W`는 Booth 때문에 짝수만.
- **설계 노트 `.docx` 원본은 구버전**이다. 최신본은 `.md`(O3, O4, O5, O6, O8, O9, O10, F4, F11 갱신 반영).
- **옛 `2_SIM/FUNCTION/` 스크립트(`run_function.tcl`)는 이 프로젝트와 무관한 UART 프로젝트용**이다. 이 프로젝트의 시뮬은 `run_regress.sh`를 쓴다.
- 이론 비교(단 수, 셀 수)는 RTL에서 센 값이고, 실제 면적과 지연은 합성 리포트가 나온 뒤에만 판단할 수 있다.

## 부록 B. 면접에서 설명할 때 쓰는 한 줄

- **무엇을 만들었나**: "같은 포트의 ALU/MAC을 덧셈기 5종, 시프터 2종, 곱셈기 3종, 파이프라인 3단계로 파라미터만 바꿔 갈아 끼우게 만들고, 합성 비교의 전제가 되는 기능 동등성을 해시로 증명했다."
- **왜 래퍼를 씌웠나**: "입출력 제약의 영향을 빼고 레지스터 사이 경로만 공정하게 비교하려고."
- **왜 덧셈기를 한 곳(`adder_top`)으로 모았나**: "프로젝트 전체의 덧셈 구조를 파라미터 하나로 바꾸려고, 그리고 `+`가 숨어 있으면 툴이 구조를 마음대로 정해 비교가 무의미해지니까."
- **부호 곱셈은 어떻게**: "Array는 Baugh-Wooley로 부호 비트가 걸린 부분곱만 반전하고 상수를 더해 모든 가중치를 양수로 만들었고, Booth는 같은 원리로 부분곱 부호 확장을 MSB 반전과 상수 보정으로 없앴다."
- **MAC을 왜 곱셈 쪽만 쪼갰나**: "누산 루프에 레지스터를 넣으면 한 클록에 한 번 더하는 동작이 바뀌어 결과가 달라지니까. 그래서 루프(`acc_q → 덧셈 → acc_q`)는 줄어들지 않고, 파이프라인을 늘려도 클록 주기에 하한이 생긴다."
- **검증은 어떻게 믿나**: "기대값을 DUT 수식과 다른 방식으로 계산하고, 모든 구조 조합의 출력 해시가 같음을 확인하며, 일부러 넣은 버그 33개가 전부 잡히는지 확인했다."
