# mul_booth_csa (Booth radix-4 + Wallace, carry-save 출력)

**하는 일**: 부호 있는 `a`, `b`(A_W비트, 짝수)를 곱하되 마지막 덧셈 없이 두 벡터 `o_s`, `o_c`로 내보낸다. 약속은 Array와 같다: `o_s + o_c ≡ a×b (mod 2^(2·A_W))`.

**먼저 용어 세 개**
- **Booth 인코딩(radix-4)**: `b`를 2비트씩 묶어 숫자 하나(−2, −1, 0, 1, 2 중 하나)로 바꾸는 방법. 비트마다 부분곱을 만들면 A_W줄이지만, 이렇게 하면 **A_W/2줄**로 줄어든다. 숫자 k는 `b[2k+1], b[2k], b[2k−1]` 세 비트(맨 아래 `b[−1]=0`)로 정하고 값은 `−2·b[2k+1] + b[2k] + b[2k−1]`이다. 부호 있는 `b`에도 그대로 맞아서 부호 처리가 따로 필요 없다.
- **Wallace 트리**: 여러 줄을 3줄씩 묶어 CSA(3:2 압축기)로 "합 줄 1 + 올림 줄 1"로 바꾸는 걸 반복해서 두 줄만 남기는 구조. 줄이 9개면 단(level)이 4번, 5개면 3번이면 끝난다(Array는 줄 수만큼 직렬).
- **부호 확장 제거**: 부분곱이 음수일 수 있어서 위쪽을 부호 비트로 채우면 가산기가 낭비된다. 이를 없애는 트릭이 아래 3번이다.

**구조** (블록 하나씩)
1. **Booth 선택 신호** (줄 k마다): `one = b[2k] ^ b[2k−1]` (크기 1), `two = (b[2k+1]&~b[2k]&~b[2k−1]) | (~b[2k+1]&b[2k]&b[2k−1])` (크기 2), `neg = b[2k+1]` (빼기).
2. **부분곱 줄**: `a`(n+1비트로 부호 확장) 또는 `2a`를 `one`/`two`로 고르고, `neg`와 XOR해서 음수는 비트를 뒤집는다(1의 보수). 뒤집으면 −x가 아니라 −x−1이 되므로 빠진 "+1"은 `neg` 비트로 따로 줄 k의 자리(2k)에 더한다.
3. **부호 확장 제거 + 상수 보정**: 줄의 부호 비트 s는 가중치가 −2^n이다. `−s·2^n = (~s)·2^n − 2^n`이므로, 줄마다 부호 비트 자리에 `~s`를 놓고 빠진 `−2^(n+2k)`들은 모아서 상수 하나 `K = −2^n·(2^n−1)/3 (mod 2^(2n))`로 더한다. (A_W=4이면 K = 0xB0.)
4. **상수 줄**: K의 아래쪽 n비트는 전부 0이고, `neg` 비트들은 아래쪽 n비트(짝수 자리)에만 있다. 겹치지 않아서 **줄 하나**에 같이 넣는다. 그래서 트리 입력은 `A_W/2 + 1`줄이다 (A_W=4, 8, 16이면 3, 5, 9줄).
5. **Wallace 트리**: 줄을 3개씩 묶어 합 줄(XOR)과 올림 줄(다수결, 왼쪽으로 1칸 이동)로 바꾸고, 남는 줄(1~2개)은 그대로 통과. 두 줄이 남을 때까지 반복(각각 1, 3, 4단). 마지막 두 줄이 `o_s`, `o_c`다. 최상위 비트 밖으로 나가는 올림은 버린다(2^(2·A_W)로 나머지).

**왜 이렇게 (설계 결정)**
- **O5 결정(승인됨)에 따라** Array의 Baugh-Wooley와 같은 계열인 "MSB 반전 + 상수 보정"으로 부호를 처리했다. 포트폴리오에서 두 곱셈기의 부호 처리를 한 이야기로 설명할 수 있다.
- **트리를 줄 단위로 일반화**: 줄이 3, 5, 9개인 세 경우(A_W=4, 8, 16)를 손으로 따로 그리지 않고, 줄 수와 단 수를 상수 함수로 계산해서 `generate`로 단을 만들었다. 모든 단의 모든 줄은 패킹 벡터 `w_all`의 한 조각(`(단 시작 위치 + 줄 번호)·P_W`)이고, 계층 참조는 쓰지 않았다. lint 순환 의심은 `split_var`(lint 전용 힌트)로 풀었다.
- 압축기는 XOR/AND/OR뿐이고 `+ - *`는 데이터에 없다. 상수 K를 만드는 식(`-((2**A_W)*((2**A_W-1)/3))`)만 elaboration 때 한 번 계산된다.
- 경계는 O5대로 **압축 끝**에서 자른다. 3단 MAC에서 `o_s`/`o_c` 자리에 `s_q`/`c_q`가 들어간다.

**합성 단계에서 볼 가설** (수치 단정 아님)
- 부분곱 줄이 절반이고 트리 단이 적어서 Array보다 **깊이가 짧을 것**이다. 반면 Booth 인코더와 선택 mux 때문에 줄당 셀과 배선은 복잡해서, A_W=16에서는 이득이 있어도 A_W=4, 8에서는 차이가 작거나 뒤집힐 수 있다.
- 합성 툴이 `*`(BEH)를 이미 Booth 계열로 만드는지, 이 RTL 구조가 합성 후에도 유지되는지가 핵심 질문이다.

**검증** (이 단계에서 내가 실제로 한 것만)
- Verilator `-Wall` 경고 0 (A_W=4, 8, 16), Yosys `read_verilog`와 `check -assert` 문제 0.
- 몇 초짜리 스모크 테스트: `o_s + o_c == a×b`를 A_W=4, 8 **전수**로 확인, 불일치 0. A_W=16은 랜덤 2만 개 + (−32768)² 불일치 0.
- **회귀(`run_regress.sh`)는 돌리지 않았다.** `MULT_ARCH=2`가 `MULT_ARCHS`에 추가되어 있으니 `tb_mul_csa_top`, `tb_mul_top`(100만 랜덤), `tb_mac_top` 조합이 돌 때 결과를 확인해야 한다.
