# adder_rca (2단계용, 보관 중)

**하는 일**: 리플 캐리 덧셈기. 비트마다 캐리가 다음 비트로 줄줄이 넘어간다.

**구조**: 비트별 propagate `p = a^b`, generate `g = a&b`, 캐리 `c[i+1] = g[i] | (p[i] & c[i])`, `sum = p ^ c`.

**이번에 한 정리**: `timescale` 제거, `default_nettype` 추가, 헤더 주석 추가. 로직은 그대로.

**O10 확인 결과**: 벡터 방식 그대로 Verilator `-Wall`에서 경고 0이었다(순환 경고 없음). 그래서 비트별 generate로 바꾸지 않았다. 단 `adder_top`을 통해 연결했을 때 기준이며, `adder_top`과 함께 `ADDER_ARCH=0` 시뮬 통과(W=8 전수).

**합성 가설**: 가장 작고 가장 느린 덧셈기일 것이다. W가 클수록 캐리 체인이 길어져서 지연이 선형으로 늘 것 같다.
