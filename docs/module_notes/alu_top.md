# alu_top

**하는 일**: `alu_core` 앞뒤에 레지스터를 붙인 ALU 최상위. 나중에 합성할 때 "레지스터 → 조합 로직 → 레지스터" 경로(reg-to-reg 경로)만 보이게 만들어, 입출력 핀 제약 때문에 생기는 영향 없이 구조끼리 공정하게 비교하려는 래퍼(wrapper, 감싸개)다.

**구조** (블록 하나씩)
1. **입력 레지스터**: `a_q, b_q, op_q`(데이터)와 `valid_in_q`.
2. **`alu_core`**: 입력 레지스터 출력을 받는 순수 조합 회로.
3. **출력 레지스터**: `result_q`, `flag_q`(= zero, neg, carry, ovf 4비트), `valid_out_q`.
4. 지연(latency) 2에지: 입력이 에지 n에 입력 레지스터에, 에지 n+1에 출력 레지스터에 잡힌다. 매 클록 1건 처리한다.

**왜 이렇게**
- **리셋은 valid에만 건다** (비동기 assert, active-low). 데이터 레지스터는 리셋도 enable도 없다. 리셋 회로와 enable mux가 없으니 면적이 줄고, 레지스터 입력(D) 경로가 짧아진다. 데이터는 "valid=1일 때만 의미 있다"는 규칙으로 해석하고, 이 정책은 모든 변형에 똑같이 적용한다.
- **비동기 리셋(asynchronous reset)**: 클록과 상관없이 리셋 신호가 내려가는 즉시 레지스터가 0이 된다. 그래서 리셋 중에 입력이 들어와도 `o_valid`는 바로 0이다.
- 리셋 해제는 클록에 맞춰 들어온다고 가정한다(노트의 가정). 테스트벤치도 클록 하강 에지에서 해제한다.

**합성 단계에서 볼 가설** (수치 단정 아님)
- 레지스터 사이 경로가 `alu_core` 하나라서, 가장 긴 경로(P1: `b XOR sub` → 덧셈기 → ovf/SLT → 결과 mux → zero 검출)가 클록 주기를 정할 가능성이 크다. 덧셈기 구조 차이가 여기서 드러나는지가 T3 측정의 핵심이다.
- 데이터 레지스터에 리셋이 없으니 같은 비트 수 대비 셀이 더 작을 것이다. 리셋 유무 실험은 4단계(선택)에서 한다.
- 레지스터 비트 수는 XLEN=32 기준 입력 69 + 출력 37 = 106개다(노트 표와 일치).

**검증** (`2_SIM/TESTBENCH/tb_alu_top.v`, V9)
- 리셋 중에 `i_valid=1`을 계속 넣어도 `o_valid=0`인지, 리셋 직후 클록 중간에도 0인지 확인.
- 입력 하나를 넣고 에지 1 뒤에는 `o_valid=0`, 에지 2 뒤에 `o_valid=1`과 정확한 결과가 나오는지 직접 확인(지연 2에지).
- 랜덤 스트림: valid가 25% 비는 갭, 연속 valid, 16개 코드 전부, 클록 중간에 랜덤 비동기 리셋(리셋 때 파이프라인에 있던 결과가 버려지는 것까지 모델이 반영). 매 사이클 2단 파이프라인 모델과 비교하고, `o_valid=0`일 때 결과/플래그는 비교하지 않는다(don't care).
- 변이 테스트: valid 리셋 제거(출력/입력 각각), 지연 1에지로 단축, carry/ovf 플래그 뒤바뀜, `op_q` 우회, 동기 리셋으로 바꿈 → 6가지 모두 FAIL로 잡혔다.
- 출력 해시가 `ADDER_ARCH` 0, 4에서 완전히 같다(V10).
