# mac_top (MAC_STAGES = 1)

**하는 일**: MAC(Multiply-Accumulate, 곱해서 누적하는 회로). 매 클록마다 명령 `(i_a, i_b, i_en, i_clr)`를 받아 누산기 `acc`를 갱신한다.
- `i_clr=1`: `acc ← 0` (곱은 무시. `i_en`보다 우선)
- `i_clr=0, i_en=1`: `acc ← acc + a×b` (포화 없이 2^ACC_W로 wrap)
- 둘 다 0: `acc` 유지

**구조** (블록 하나씩)
1. **입력 레지스터**: `a_q, b_q`(데이터, 리셋 없음)와 `en_q, clr_q`(제어, 비동기 리셋).
2. **`mul_top`**: 입력 레지스터의 `a_q × b_q`를 계산 (signed, 2·A_W비트 곱).
3. **부호 확장**: 곱을 ACC_W비트로 맞춘다. 음수 곱이면 위쪽을 1로 채워야(부호 확장, sign extension) 2의 보수 덧셈이 맞는다.
4. **`adder_top`**: `acc_q + 확장된 곱`. 누산 덧셈도 반드시 `adder_top`을 지난다.
5. **누산기 `acc_q`**: 다음 값을 `clr_q`(0으로) → `en_q`(합) → 그 외(유지) 순서로 고르고, 비동기 리셋을 가진다. `o_acc`는 `acc_q` 그대로다.

**지연(latency)**: 2에지. 에지 n에 명령이 입력 레지스터에 잡히고, 에지 n+1에 `acc_q`가 갱신된다 (`MAC_STAGES + 1`).

**왜 이렇게**
- **누산 루프(`acc_q → 덧셈기 → acc_q`)는 1사이클, 안에 레지스터를 넣지 않는다.** 루프 안에 레지스터를 넣으면 한 클록마다 한 번 더하던 것이 두 클록에 한 번이 되어 결과 자체가 달라진다. 그래서 파이프라인 단 수(`MAC_STAGES`)는 곱셈 쪽에서만 나눈다(2, 3단은 3단계 작업).
- **리셋은 상태 레지스터만**: `acc_q`, `en_q`, `clr_q`. 리셋 직후에는 `en_q = clr_q = 0`이라 `a_q × b_q`가 아직 쓰레기여도 누산에 반영되지 않아 `o_acc`가 항상 정의된다. 그래서 `valid` 포트가 필요 없다.
- **`i_clr` 우선(O6, 승인됨)**: `clr`와 `en`이 동시에 1이면 `acc ← 0`.
- **`ACC_W = 2·A_W + 8`**: 가드 비트 8개. 최악의 곱 (−2^(A_W−1))² = 2^(2A_W−2)를 연속으로 더하면 511번까지는 부호 있는 범위 안이고 512번째에 wrap한다(어느 A_W든 같다).
- **지원하지 않는 `MAC_STAGES`(2, 3)나 `A_W`는 컴파일 에러**로 막았다(1단으로 조용히 대체하지 않음).
- `adder_top`의 carry-out은 일부러 쓰지 않는다(wrap이라 필요 없음). Verilator의 UNUSEDSIGNAL 경고를 이 이유로 명시적으로 껐다.

**합성 단계에서 볼 가설** (수치 단정 아님)
- 1단에서는 가장 긴 경로가 `a_q/b_q → 곱셈 → 누산 덧셈 → acc_q`(Q1)일 가능성이 크다. 곱셈기 구조 차이(BEH/Array/Booth)가 여기서 가장 크게 드러날 것 같다.
- 2단, 3단으로 나누면 곱셈 경로는 짧아지지만 `acc_q → 덧셈 → acc_q`(Q2)는 줄어들지 않아서 클록 주기에 하한이 생길 것 같다.

**검증** (`tb_MAC.v`, M3, M4, M5, M7)
- 모델은 명령을 에지에서 즉시 반영하고, DUT의 `o_acc`는 `MAC_STAGES`에지 전 모델 값과 비교한다.
- A 단계 리셋 없는 랜덤, B 단계 클록 중간 비동기 리셋 포함 랜덤(파이프라인 안의 명령이 버려지는 것까지 반영), C 단계 최악의 곱 511회/512회(wrap 경계), D 단계 리셋 직후 0과 복구.
- A_W 4, 8, 16을 전부 돌렸다(M7). `clr/en` 4가지 조합, 양/음 곱, 누산 중 부호 변화, wrap 발생, 리셋 중간 인가를 도달 확인으로 센다.
- 변이 테스트 8가지(en 우선, 부호 확장 제거, 리셋 제거 2종, clr 지연 우회, b_q 우회, carry-in 오류, 음수 포화) 모두 FAIL로 잡혔다.
- `ADDER_ARCH` 4, 0에서 정렬된 출력 해시가 같다(M6 방식은 3단계에서 MAC_STAGES 사이로 확장).
