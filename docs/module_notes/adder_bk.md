# adder_bk (Brent-Kung 덧셈기)

**하는 일**: 병렬 prefix 덧셈기 중 "작은 쪽 끝". Kogge-Stone(KS)보다 셀과 배선이 훨씬 적고, 대신 논리 단 수가 거의 두 배다. 포트는 모든 덧셈기와 같다.

**먼저 용어**: **prefix 네트워크**는 "비트 i~0 전체의 올림"을 모든 i에 대해 구하는 회로고, 구간 두 개 `(G_hi, P_hi)`, `(G_lo, P_lo)`를 `G = G_hi | P_hi·G_lo`, `P = P_hi·P_lo`로 합치는 셀로 만든다.

**구조** (블록 하나씩)
1. **전처리**: 비트마다 `p = a^b`, `g = a&b`. carry-in은 비트 0의 g에 흡수(`g0' = g0 | p0·cin`).
2. **up-sweep(올라가기)**: 단 d=0..L−1 (L = ceil(log2 W)). `(i+1)`이 2^(d+1)의 배수인 비트 i가 `i−2^d`와 합쳐진다. 끝나면 비트 2^k−1이 "비트 0~2^k−1 전체"의 G를 갖는다. (나무 모양으로 모으기)
3. **down-sweep(내려오기)**: 단 d=L−2..0. `(i+1) = 3·2^d + t·2^(d+1)`인 비트가 `i−2^d`와 합쳐져서, 나무 중간에 비어 있던 비트들의 올림을 채운다. 끝나면 모든 `G_i`가 비트 i~0 전체의 G, 즉 비트 i의 carry-out이다.
4. **후처리**: `c_0 = cin`, `c_(i+1) = G_i`, `sum_i = p_i ^ c_i`, `o_cout = G_(W−1)`.
- 단 수는 up L개 + down L−1개 = `2L−1`. (W=32이면 9단, 노트의 이론값과 같다.) 단마다 (G, P)를 패킹 벡터의 한 조각으로 두고, 그 단에서 건드리지 않는 비트는 그대로 통과시킨다.
- W가 2의 거듭제곱이 아니어도 된다: 존재하지 않는 비트(인덱스 ≥ W)는 그냥 만들지 않는다. 모든 셀이 자기보다 낮은 인덱스만 읽기 때문에 결과가 달라지지 않는다.

**왜 이렇게**: KS와 같은 전처리/후처리·같은 표기를 써서 "prefix 네트워크 부분만 다르다"는 것이 코드에서 그대로 보이게 했다. 면적(셀 수)과 속도(단 수)의 교환 관계를 합성에서 직접 비교하려는 목적이다.

**합성 단계에서 볼 가설** (수치 단정 아님)
- 이론상 W=32에서 prefix 셀이 약 57개로 KS(129개)의 절반 이하라 면적과 배선이 작고, 단 수는 9단으로 KS(5단)의 거의 두 배라 더 느릴 것이다.
- 단 중간에서 일부 비트의 fanout이 커지는 곳이 있어서, 배치 단계에서 fanout 버퍼링을 볼 만하다.

**검증**: `tb_adder.v`와 `alu_core`/`alu_top`/`mac_top`에서 BEH와 출력 해시 동일. lint는 W=8~64에서 경고 0.
