# shr_barrel

**하는 일**: 오른쪽 논리 시프트 코어. 채움 비트(`i_fill`)를 밖에서 받아서 SRL(0으로 채움)과 SRA(부호 비트로 채움)에 같이 쓴다.

**구조**: 시프트양의 비트 수(8→3, 16→4, 32→5)만큼 단(stage)이 직렬로 이어진다. 단 k는 `i_shamt[k]=1`이면 2^k만큼 밀고, 0이면 그대로 통과(비트마다 2:1 mux). 각 단 결과는 한 벡터에 `[k*XLEN +: XLEN]`로 슬라이스해서 둔다.

**왜 이렇게**
- `>>` 같은 가변 시프트 연산자를 안 쓰고 mux를 직접 그렸다. 연산자를 쓰면 툴이 구조를 고르기 때문에 `shr_loop`와 비교가 안 된다.
- `$clog2`를 안 쓰고 XLEN이 8/16/32뿐이라는 점을 이용해 `SHAMT_W`를 직접 계산했다(툴 호환 문제 회피).
- `/* verilator split_var */`는 lint 전용 주석이다. 한 벡터 안의 슬라이스끼리 단방향으로 이어진 걸 Verilator가 순환(UNOPTFLAT)으로 오해해서 붙였다. 합성에는 영향 없다.

**합성 가설**: 단 수가 log2(XLEN)이라 경로가 짧고(mux 5개 정도), 대신 mux가 많아 면적은 loop 방식보다 클 것 같다.
