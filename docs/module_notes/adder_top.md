# adder_top

**하는 일**: 설계 안의 모든 덧셈이 지나가는 단일 입구. `ADDER_ARCH` 값으로 덧셈기 구현을 고른다.

**구조**: `generate if`로 `adder_rca`(0) 또는 `adder_beh`(4, 기본) 하나만 인스턴스. 포트는 어느 쪽이든 동일.

**왜 이렇게**
- 1, 2, 3(CLA / Kogge-Stone / Brent-Kung)은 코드만 예약돼 있다. 아직 없는 값이 들어오면 **존재하지 않는 모듈**(`adder_arch_not_implemented`)을 인스턴스해서 컴파일 단계에서 에러가 나게 했다. 조용히 BEH로 바꿔 끼우면 "RCA라고 믿고 합성했는데 사실 BEH"인 사고가 나기 때문이다.
- generate 구조는 1단계부터 만들어 둬서, 2단계에서 KS 등을 추가할 때 분기만 늘리면 된다.

**합성 가설**: 이 모듈 자체는 배선뿐이라 면적·타이밍 차이는 안쪽 덧셈기에서 나온다. 합성 후에도 `u_adder` 경계가 남아 있는지 확인하면 구조 유지 여부를 볼 수 있다.

**검증**: `tb_adder.v` — W=8 전수(a, b, cin 모든 조합), W=16/32는 코너 + 고정 시드 랜덤. ARCH 4, 0 모두 통과.
