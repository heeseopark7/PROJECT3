# mul_top

**하는 일**: 곱셈기의 단일 입구. `MULT_ARCH`로 곱셈기 구현을 고른다(0 BEH, 1 Array, 2 Booth+Wallace). 포트는 `i_a, i_b → o_p`로 모두 같다.

**구조**: `generate if`로 `mul_beh`(0)를 인스턴스한다. 1, 2는 코드만 예약돼 있다.

**왜 이렇게**: 아직 없는 `MULT_ARCH`(또는 지원하지 않는 `A_W`)가 들어오면 **존재하지 않는 모듈**(`mul_arch_not_implemented`)을 인스턴스해서 컴파일 단계에서 에러가 난다. `adder_top`, `alu_shifter`와 같은 규칙이다. 구조형 곱셈기는 최종 합산에 `adder_top`을 쓰므로 2단계에서 `ADDER_ARCH` 파라미터를 추가한다. 지금은 쓰이지 않는 파라미터가 되어 lint 경고가 나기 때문에 아직 넣지 않았다.

**합성 가설**: 이 모듈 자체는 배선뿐이고 차이는 안쪽 곱셈기에서 나온다. 합성 후에도 `u_mul` 경계가 남아 있는지로 구조 유지 여부를 볼 수 있다.

**검증** (`tb_mul.v`, M1, M2): A_W=4, 8은 모든 (a, b) 전수(65,536개 포함), A_W=16은 코너 49쌍(−32768×−32768 포함) + 고정 시드 100만 랜덤. 양×양, 음×음, 양×음, 0, min×min 도달 확인 100%.
